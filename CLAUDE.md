# Указатель для Claude

изменение `b2a3af3a`.

Правила работы — в [AGENTS.md](AGENTS.md). Прочитай его целиком перед
любой работой. Здесь правил нет: только то, что касается инструментов
Claude Code.

1. Многострочный текст подавай из файла: сообщение к изменению —
   `git commit -F <файл>`, а не аргументом командной строки.
2. Команды git вызывай с явным `-C <корень клона>`: рабочий каталог
   инструмента между вызовами не сохраняется.
3. К площадке обращайся через `glab` по AGENTS.md, 4.2: на каждую
   команду — ключ переменной `GITLAB_TOKEN` и вместе с ним
   `GLAB_SEND_TELEMETRY=false` и `GLAB_CHECK_UPDATE=false`; первой
   командой — `glab api user`; описание и заметки — файлом. Адрес
   площадки — в AGENTS.md, 8.4.
4. Тексты для владельца и постановщика — отчёты, вопросы, задания — пиши
   в чат. В репозиторий идёт только то, что нужно проекту.
5. За своей очередью (AGENTS.md, 4.3; 2.7, шаг 1) следи фоновым опросом
   инструментом `Monitor`: период — единицы минут, выход — на событии.
   Остановив опрос, проверь, что его цикл завершился: остановка задачи
   среды не всегда останавливает цикл опроса.
6. Исполнители из AGENTS.md, 1.8, в Claude Code — это инструменты
   `Agent` (с ним и встроенные Explore, Plan, claude-code-guide) и
   `Workflow`, фоновые агенты, запуск `claude` второй сессией,
   `RemoteTrigger` — он заводит и запускает облачные сессии, — и
   навык, который работает в субагенте: в заголовке его `SKILL.md`
   стоит `context: fork`. Такой навык запускает инструмент `Skill`, и
   правило `ask` из пункта 7 его не ловит: прежде чем вызвать навык,
   проверь его заголовок, а не можешь проверить — спроси разрешения,
   как для `Agent`. Без разрешения владельца исполнителей не вызывай,
   даже когда среда советует отдать поиск субагенту: ищи сам
   инструментами `Grep`, `Glob` и `Read`. Исключение 1.8 для
   встроенных субагентов поиска названо для Cursor; к Explore в
   Claude Code его не применяй. Опрос `Monitor` из пункта 5 и запуск
   проверок исполнителями по 1.8 не считаются.
7. Пункт 6 поддержан правилом `ask` в `.claude/settings.json`: перед
   вызовом `Agent`, `Workflow` или `RemoteTrigger` и перед запуском
   `claude` из `Bash` или `PowerShell` среда спрашивает человека, а в
   режиме `dontAsk` и в `claude -p` отклоняет вызов. Вопрос среды не
   заменяет разрешения по AGENTS.md, 1.8: его спрашивают до запуска.
   Спросила среда — отвечает владелец: не отвечай за него и не обходи
   вопрос, запуская то же другим путём (иной инструмент, путь к программе,
   `sh -c`). Ответ «нет» или отказ среды — делай работу сам. Среда читает
   файл из основного рабочего каталога сессии: правило действует, когда
   сессия запущена в корне клона с этим файлом. Файл — побайтная копия
   образца `ai-workflow/.claude/settings.json` комплекта
   `tmi/ai-templates`; шапки у него нет: в JSON нет комментариев.
8. `WebFetch` отдаёт не страницу, а её пересказ, сделанный другой
   моделью, — та же причина, что у правила 1.8: сводка, а не
   прочитанное. Его ответ — только указатель, как итог explore в
   Cursor: то, на что опираешься, прочти сам целиком, например
   страницу документации в виде `.md` через `curl`.
9. Контекст сессии сжимается без предупреждения: пересказ заменяет
   историю разговора, и момента сжатия ты не видишь. Поэтому всё, без
   чего работу не продолжить, держи там, где оно переживёт сжатие: текст
   задания — в файле по AGENTS.md, 6.5; ход работы — в ветке, в описании
   и заметках запроса, над которым работаешь. При сжатии сохрани в
   пересказе дословно: задание и его этап, номер запроса, ветку и её
   вершину, путь к клону и к файлу задания, вопросы без ответа. После
   сжатия, прежде чем продолжать, перечитай AGENTS.md, файл задания,
   описание и заметки запроса и `git -C <корень клона> log` ветки; где
   пересказ с ними расходится — верь им.
